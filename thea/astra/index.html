Thea: Towards the Harness of Embodied Agents

Revisited after GPT-6 Astra

HAI Lab · Eastern Institute of Technology, Ningbo

01Tools 02Harness 03What remains

Abstract. Thea carried the harness paradigm of coding agents into the physical world, adding a persistent readable world state (Scene Graph as Context) and verifiable action-outcome judgments (Evaluation as Exit Codes). With GPT-6 Astra given a robot SDK inside Codex, we revisit tool granularity, which components come from the model or coding harness, and which still need to be built for the physical world.

01

Revisiting the Tools

Thea originally exposed skill-level tools such as pick, place and navigate_to. Here we gave GPT-6 Astra, running in Codex, the Astribot S1 Python SDK and its documentation, with no Thea component present, and asked for the four left parallel-gripper tasks below.

The agent corrected early geometric errors and all four tasks reached the displayed final states: objects in the plate, a retrieved cube and closed drawer, and a loaded bowl delivered to the destination table. For these tasks, the model constructed control code rather than invoking a learned manipulation policy. The drawer video combines two sessions.

The agent registered head-camera RGB-D observations in the base frame, solved inverse kinematics numerically against the SDK’s forward kinematics, screened joint samples for self-collision, and sent one motion segment at a time. Base movement used velocity pulses gated by lidar clearance.

02

Revisiting the Harness

Model · coding harness · what remains

Codex supplied the agentic loop, tool execution, files and the write-run-read-fix cycle. The runs revisit who supplies Thea’s physical-world components: world state and spatial memory, evaluation, body limits, and skills.

World state and spatial memory

The paper compares three paired five-target tasks from HabitatGS-Benchmark, released with SuperNav: Astra without prescribed scene-graph memory versus Astra instructed to maintain it. Each task has one run per condition, a 500-action cap and a 1m arrival threshold.

With instructed graph memory, completion rose from 2/3 to 3/3, and mean SPL from 0.485 to 0.690 (+42.3%). SPL weights task success by the shortest-to-actual path-length ratio, with failures scored zero.

Without prescribed graph memory, targets were re-localized from images and earlier sightings retained in conversation. With instructed graph memory, room and route records were stored and later reused. The videos, context streams and Workspaces show how these model-estimated records informed route choices and revisits.

The page also includes the navigation-evaluation condition and LHPR-VLN, for 18 records in total. The evaluation condition completed 0/3 HabitatGS tasks; all nine LHPR runs were incomplete. Completion labels follow each run’s native STOP rule.

Evaluation

In the Revo2 cup-grasping trials, the wrist reached its motion target while the cup stayed on its support. Post-action images exposed the difference between command completion and the object’s actual state.

In two cup-rim attempts, the wrist rose about 7.58 mm while the cup remained on the plate. The task agent used post-action image checks to reject the unsuccessful lifts and adjust its grasp.

Body limits

After Revo2 was installed, the collision model still described a parallel gripper. The agent identified this mismatch, and human-prompted landmark checks compared the current hand with calibrated model projections.

At a fixed hand shape, human-prompted geometry checks measured local per-finger landmark RMS errors of 1.35–2.20 mm. After slight finger closure, overall RMS was 5.26 mm, with a 9.57 mm maximum. The geometric error changed with the hand configuration.

Skills and memory

Modules written for the first S1 left-gripper task, including capture, localization, inverse kinematics and collision screening, were reused in the other three and accumulated as files in the workspace.

The navigation Workspaces provide a separate record of helpers, scripts and model-written world state. The provided, modified and new labels distinguish the starting interface from files produced or changed during the run.

03

What Changes and What Remains

The runs still had to re-sense the world and judge their outcomes. After Astra, the model can write more of the control stack, while the harness takes on more explicit responsibility for body constraints, safety and outcome evaluation.

01

Tool granularity blurs downward

Thea exposed skill-level tools backed by policies or stacks. Here the model wrote motion segments against the SDK, so the harness needs to expose the body at several control levels.

02

The Embodiment Profile does more work

When the model emits poses directly, kinematic limits, workspace bounds and calibration can no longer stay hidden inside a policy. The Embodiment Profile must make them explicit to support cross-embodiment use.

03

Safety moves into the harness

At SDK-level control, permissions and sandboxes must become physical workspace bounds, collision checks and force limits. The lower the control abstraction, the heavier this safety layer must be.

04

The evaluator is a precondition for physical-world self-improvement

Digital self-improvement could rely on exit codes and unit tests. The physical world does not provide equivalent task-outcome judgments for free, so Evaluation as Exit Codes must come first.
